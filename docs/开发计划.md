# AI 求职顾问 Phase 1 开发计划

> 版本：V1.0  
> 目标：个人开发者 7 天内完成本地可运行 Demo  
> 当前状态：Phase 1 开发与工程验收已完成  
> 更新日期：2026-08-03

## 1. 最终目标

在 7 个开发日内完成：

```text
输入招聘 JD 文本
  → 调用 DeepSeek API
  → 返回 analysis-v1 JSON
  → 网页展示结构化岗位分析
```

Phase 1 只交付这一条主流程。

## 2. 开工条件

- DeepSeek API Key 可用；
- DeepSeek 账户有可用余额；
- 开发环境能够访问 DeepSeek API；
- 确认使用非思考模式和 JSON Output；
- 确认 [analysis-schema.md](analysis-schema.md) 为唯一输出协议；
- 确认本地 Demo 为强制交付，公开部署不是阻塞项；
- 准备 5–10 条脱敏 JD 测试样例。

## 3. Phase 1 任务范围

### 3.1 项目初始化

- 初始化 Next.js、TypeScript 和 Tailwind CSS；
- 选择并锁定 Node.js 版本和包管理器；
- 配置 lint、测试和构建命令；
- 创建 `.env.example`，不写入真实密钥；
- 更新 README 本地运行说明。

### 3.2 数据契约

- 按 `analysis-v1` 建立运行时 Schema；
- 从 Schema 推导或同步 TypeScript 类型；
- 建立请求 Schema；
- 建立证据字符串包含校验；
- 保证 API、Prompt 和前端字段一致。

### 3.3 DeepSeek 服务端调用

- 实现 `POST /api/analyze`；
- 使用服务端环境变量；
- 使用 DeepSeek 非思考模式；
- 使用非流式 JSON Output；
- 设置 60 秒应用级总超时；
- 实现一次性重试策略；
- 映射上游和内部错误；
- 不向前端暴露模型原始错误或密钥。

### 3.4 页面

- JD 多行文本输入；
- 100–12,000 字符校验；
- 隐私提示；
- 开始分析按钮；
- 初始、加载、成功和错误状态；
- 错误后保留 JD 并支持重试；
- 按协议展示岗位基本信息、核心职责、岗位真实画像、投递建议和 HR 消息；
- `candidateAdvantages` 为 `null` 时不展示；
- 基础响应式布局。

### 3.5 测试与验收

- 输入请求校验测试；
- `analysis-v1` Schema 测试；
- 证据校验测试；
- DeepSeek 成功和错误模拟测试；
- 页面四类状态测试；
- 5–10 条脱敏 JD 人工回归；
- lint、测试和生产构建；
- 本地真实 API 演示。

## 4. 七天推荐顺序

### Day 1：初始化与冻结契约

- 初始化项目；
- 锁定 Node.js 和包管理器；
- 创建请求 Schema、`analysis-v1` 运行时 Schema 和类型；
- 配置环境变量名称；
- 确认文档字段与 Schema 一致。

完成标准：项目可启动，数据契约可被测试引用。

### Day 2：DeepSeek 链路

- 创建 Prompt；
- 封装 DeepSeek 调用；
- 配置非思考、JSON Output 和生成参数；
- 打通一条真实 JD 的服务端调用；
- 完成 JSON 和 Schema 校验。

完成标准：服务端能返回合法的 `analysis-v1` 数据。

### Day 3：接口异常处理

- 完成 `/api/analyze`；
- 实现 60 秒总超时；
- 实现一次性重试；
- 映射 400、401、402、422、429、500、503；
- 处理空内容、无效 JSON 和异常结束原因。

完成标准：成功和主要错误路径都有稳定响应。

### Day 4：页面主流程

- 完成 JD 输入和校验；
- 接入分析接口；
- 完成初始、加载、成功、错误和重试；
- 保留失败输入；
- 防止重复提交。

完成标准：用户可以完成一次端到端分析。

### Day 5：结果展示与响应式

- 展示岗位基本信息；
- 展示核心职责；
- 展示岗位真实画像；
- 展示投递建议；
- 隐藏空的优势分析；
- 展示通用 HR 打招呼消息；
- 完成移动端基础布局。

完成标准：所有协议字段被正确消费，空状态不破坏页面。

### Day 6：Prompt 回归与自动测试

- 使用固定 JD 样例回归；
- 检查硬门槛、加分项、推断和证据；
- 检查提示注入；
- 模拟 DeepSeek 错误；
- 完成核心自动测试。

完成标准：关键分类规则稳定，错误路径可恢复。

### Day 7：验收与文档

- 按 PRD 验收；
- 修复阻断问题；
- 执行 lint、测试和构建；
- 更新 README 和更新日志；
- 整理演示 JD 和演示步骤。

完成标准：本地 Demo 可重复运行和演示，不需要临时修改代码。

## 5. Phase 1 验收清单

- [x] 页面只接收 JD 文本；
- [x] 有效 JD 可提交，非法长度被拦截；
- [x] API Key 只存在于服务端；
- [x] 使用 DeepSeek 非思考模式；
- [x] 使用 JSON Output；
- [x] 返回数据通过 `analysis-v1` 校验；
- [x] 关键结论可追溯到 JD 原文；
- [x] 投递建议不表示用户匹配度；
- [x] `candidateAdvantages` 为 `null` 且前端不展示；
- [x] `hrGreeting` 不编造用户经历，且 `personalized` 为 `false`；
- [x] 超时、上游错误和输出错误有明确处理；
- [x] 失败后保留 JD 并可重试；
- [x] 桌面和移动视口可使用；
- [x] lint、测试和生产构建通过；
- [x] README 与更新日志完成同步。

## 6. 明确延期

以下内容不进入本开发计划：

- 登录注册；
- 数据库；
- 文件上传；
- OCR；
- 历史记录；
- 会员系统；
- 权限系统；
- 投递管理；
- SSE 实时任务；
- 复杂评测系统；
- PostgreSQL；
- Redis；
- 对象存储；
- 消息队列；
- 用户经历录入；
- 个性化优势分析；
- 人岗匹配；
- 面试准备；
- 公开部署。

这些功能只有在 Phase 1 验收完成并获得新指令后才能进入计划。

## 7. 范围控制

- 开发中出现的新想法先记录，不直接实现；
- 不为延期功能提前建设数据库或抽象层；
- 不因模型偶发失败引入复杂多模型或任务系统；
- 核心主流程、可解释性和错误恢复优先于视觉动效；
- 所有范围变更必须先更新 PRD 和开发计划。
