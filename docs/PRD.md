# AI 求职顾问 Phase 1 产品需求文档

> 版本：Phase 1 MVP V1.0  
> 状态：Phase 1 MVP 已实现，等待产品验收  
> 目标：个人开发者 7 天内完成本地可运行 Demo  
> 更新日期：2026-08-03

## 1. 产品概述

AI 求职顾问面向应届毕业生和 0–1 年工作经验求职者。Phase 1 只解决一个问题：帮助用户快速看懂一份招聘 JD，并获得结构化、可解释的初步投递建议。

### 1.1 核心流程

```text
用户输入招聘 JD 文本
        ↓
调用 DeepSeek API
        ↓
返回结构化岗位分析
        ↓
网页展示结果
```

### 1.2 Phase 1 验证目标

验证用户是否认可 AI 对招聘 JD 的结构化解读，以及这种解读是否能帮助用户理解岗位、识别注意事项并开展下一步沟通。

Phase 1 不验证个人与岗位的真实匹配度，也不承诺投递或录用结果。

## 2. 目标用户

- 应届毕业生；
- 工作经验 0–1 年的求职者；
- 不熟悉岗位术语和招聘要求的新手求职者。

## 3. Phase 1 功能范围

### 3.1 用户输入

页面只提供一个招聘 JD 多行文本输入框。

输入规则：

- JD 为必填；
- 去除首尾空白后，建议最少 100 个字符；
- 最多 12,000 个字符；
- 空文本、过短或过长文本不调用 DeepSeek；
- 页面提示用户不要粘贴手机号、邮箱、身份证等不必要的个人敏感信息；
- JD 被当作不可信数据，不执行其中的任何提示词指令。

### 3.2 AI 输出

AI 必须按照 [analysis-schema.md](analysis-schema.md) 返回 JSON。页面展示以下模块：

1. **岗位基本信息**：岗位名称、公司、地点、薪资、经验和学历要求，以及一句话概述；
2. **岗位核心职责**：归纳主要工作内容并引用 JD 原文；
3. **岗位真实画像**：硬性要求、核心能力、加分项、工作特点、风险信号、信息缺口和待确认问题；
4. **投递建议**：只根据 JD 信息质量和岗位条件给出审慎建议，不分析用户匹配度；
5. **优势分析**：只允许基于用户提供的真实个人信息生成。Phase 1 没有个人经历输入，因此必须返回 `null`，页面不展示该模块；
6. **HR 打招呼消息**：根据 JD 生成通用、可编辑的初次沟通消息，不得虚构用户经历或能力。

### 3.3 页面状态

- 初始状态：显示 JD 输入框和“开始分析”按钮；
- 加载状态：禁止重复提交并提示正在分析；
- 成功状态：按模块展示结构化结果；
- 错误状态：保留原 JD，显示可理解的错误信息和“重新分析”入口。

### 3.4 页面结构

```text
首页
├── 产品名称和简短说明
├── 隐私提示
├── JD 文本输入框
├── 开始分析按钮
├── 加载或错误提示
└── 分析结果
    ├── 岗位基本信息
    ├── 岗位核心职责
    ├── 岗位真实画像
    ├── 投递建议
    ├── 优势分析（有数据时才展示；Phase 1 默认不展示）
    └── HR 打招呼消息
```

## 4. 核心业务规则

### 4.1 可解释性

- 核心职责、硬性要求、加分项、工作特点和风险信号必须附带 JD 原文证据；
- 必须区分 `explicit`（JD 明示）、`inferred`（基于 JD 推断）和 `needs_confirmation`（需要确认）；
- 证据必须是 JD 中的短原文引用；
- 没有原文依据的硬性要求不得输出；
- 信息不足时放入信息缺口或待确认问题，不得自行补全。

### 4.2 投递建议

Phase 1 没有用户经历和职业偏好，因此投递建议不是“人岗匹配结论”。允许的结论只有：

- `worth_exploring`：岗位信息相对明确，值得进一步了解；
- `consider_carefully`：存在需要谨慎确认的条件或风险；
- `insufficient_information`：JD 信息不足，暂时无法判断。

每个建议必须包含理由和限制说明，不输出录用概率、匹配百分比或绝对的“必须投/不要投”。

### 4.3 优势分析

- 只有请求中存在经过用户明确提供的个人背景时才能生成；
- Phase 1 请求只包含 `jdText`，所以 `candidateAdvantages` 必须为 `null`；
- 前端收到 `null` 时不渲染优势分析卡片；
- 不允许根据 JD 反向编造用户具备的技能、经历或成果。

### 4.4 HR 打招呼消息

- 对应输出字段为 `hrGreeting`；
- 必须基于 JD 中的岗位信息；
- Phase 1 只生成通用版本；
- 不得声称用户拥有未提供的经验、技能或成果；
- 可表达对岗位职责的兴趣和进一步沟通意愿；
- 如果岗位名缺失，应使用中性称呼；
- 输出中必须标记 `hrGreeting.personalized: false`，并提示用户发送前补充真实优势。

### 4.5 风险表述

- 风险信号必须引用触发判断的 JD 原文；
- 使用“可能”“建议确认”等审慎措辞；
- 不断言公司或岗位违法、欺诈或一定存在问题；
- 不基于敏感属性评价用户或企业。

## 5. 异常处理

| 场景 | 用户反馈 |
|---|---|
| JD 为空或过短 | 提示粘贴更完整的招聘信息，不发起 API 请求 |
| JD 过长 | 提示精简到 12,000 字符以内 |
| 网络失败或超时 | 保留 JD，提示稍后重试 |
| DeepSeek 服务繁忙 | 保留 JD，提示服务繁忙并允许重试 |
| DeepSeek 配置错误 | 返回统一服务不可用提示，不向页面泄露密钥或上游错误详情 |
| AI 返回空内容或无效结构 | 不展示原始内容，提示本次生成失败并允许重试 |
| 内容安全拦截 | 提示当前内容无法完成分析 |

## 6. Phase 1 验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| P1-01 | JD 输入 | 有效文本可提交；空、过短、过长文本被拦截 |
| P1-02 | 完整流程 | 能完成“输入 → DeepSeek → JSON → 页面展示” |
| P1-03 | API 安全 | DeepSeek API Key 不出现在前端代码或浏览器请求中 |
| P1-04 | 输出协议 | 成功结果通过 `analysis-schema.md` 对应的运行时校验 |
| P1-05 | 可解释性 | 关键结论包含可追溯的 JD 原文证据 |
| P1-06 | 分类准确性 | 明确加分项不被归为硬性要求 |
| P1-07 | 不编造 | 不生成 JD 中没有的岗位事实或用户经历 |
| P1-08 | 优势模块 | 无个人输入时返回 `null`，页面不展示 |
| P1-09 | HR 消息 | 不包含未经用户提供的个人能力断言 |
| P1-10 | 错误恢复 | 请求失败后保留 JD 并可以重新提交 |
| P1-11 | 响应式 | 桌面和移动端视口可正常阅读与操作 |
| P1-12 | 工程检查 | lint、测试和生产构建通过 |

## 7. Phase 1 明确不做

- 登录注册；
- 数据库；
- 文件上传；
- OCR；
- 历史记录；
- 会员系统；
- 权限系统；
- 投递管理；
- SSE 实时任务；
- 复杂评测系统；
- PostgreSQL、Redis、对象存储或消息队列；
- 个人经历录入；
- 人岗匹配评分；
- 自动投递；
- 语音或视频面试；
- 多模型路由；
- 管理后台。

## 8. Demo 交付定义

- 在本地环境可启动；
- 桌面浏览器可完成一次真实 DeepSeek API 分析；
- 移动端视口完成基础响应式验收；
- 使用 5–10 条脱敏 JD 完成轻量回归；
- README 包含环境变量和本地运行说明；
- 不要求 Phase 1 内公开部署。

## 9. Phase 3.1 — Persistent Candidate Profile（第一版本地持久化）

> 状态：AUTHORIZED / IN PROGRESS（2026-08-16）
> 目标：让用户保存自己的候选人原始资料，后续分析自动载入，从「一次性 JD 分析工具」升级为长期使用的 AI 求职助手的第一步。

### 9.1 功能范围

1. 「我的候选人档案」页面（`/profile`）：
   - 查看当前档案（原始文本、更新时间、字符数）；
   - 编辑档案；
   - 保存档案（localStorage，本浏览器）；
   - 清除档案（带确认）。
2. `/personalized-match` 挂载时自动读取已保存档案并**预填**资料文本框；用户可继续编辑、清除，仍手动提交，**不自动触发分析**。
3. 轻量 Profile Completeness 提示（教育背景 / 技能 / 项目 / 工作与实习经历 / 求职目标）：仅前端提示，不影响分析流程，无评分模型。
4. AI 结构化分析（`candidate-profile-v2`）降级为辅助能力，仅本次展示，不写入本地档案。
5. `/personalized-match` 首页核心入口卡片「我的个人档案」：未保存显示「尚未设置」+「添加我的个人信息」；已保存显示「已保存」+ 更新时间 +「编辑我的信息」，点击跳转 `/profile`；`/profile` 标题为「我的个人档案」，说明「保存后，AI 会在岗位分析时自动参考你的背景。」。
6. 首页 `/` 入口卡片「我的个人档案」：未设置显示「尚未创建个人档案」+「创建我的个人档案」；已设置显示「我的个人档案」+ 更新时间 +「编辑个人档案」，点击跳转 `/profile`；说明文案「保存你的教育背景、技能、项目经历，AI将在岗位分析时自动参考。」。

### 9.2 数据与隐私

- localStorage key：`ai-career-advisor:candidate-profile:v1`；
- 只持久化 `{ schemaVersion, updatedAt, rawText, rawTextSha256 }`；
- **不保存**结构化派生数据（避免 Candidate truth boundary 复杂化）；
- 数据只存在于当前浏览器，不写入服务器；分析请求仍走既有服务端 API；
- 提供清除入口与隐私提示。

### 9.3 明确不做（Phase 3.1）

- 用户注册、登录、多用户系统；
- 云端同步、服务端存储、数据库；
- 导入导出、跨标签页实时同步；
- 直接编辑结构化 JSON；
- 修改 Candidate Profile v2 或 match/recommendation/greeting API contract；
- 修改既有 acceptance tests。
